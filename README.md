# Loral

Self-hosted музыкальная платформа с **личными медиатеками**: у каждого пользователя свои треки, плейлисты и избранное. Сканирование папок, парсинг имён и тегов, веб-загрузка, фоновое обогащение метаданных, Discover (чарты, новинки, жанры), перенос плейлистов из Spotify.

**Стек:** Express 5 + TypeScript, PostgreSQL + Prisma, Redis + BullMQ, music-metadata · Next.js 15 + Tailwind 4 + Zustand.

```
backend/    API, сканер, воркер BullMQ, схема Prisma и миграции
frontend/   Next.js: глобальный плеер, медиатека, Discover, импорт, админка
docker-compose.yml   PostgreSQL + Redis для разработки
```

## Быстрый старт

Нужны Node.js ≥ 20.11 (для тестов ≥ 22.6) и Docker (или свои PostgreSQL 14+ и Redis 6+).

```bash
docker compose up -d

cd backend
cp .env.example .env          # задайте JWT-секреты и пароль админа
npm install
npx prisma generate
npx prisma migrate deploy
npm run dev                   # API на :4000

cd ../frontend
cp .env.example .env.local
npm install
npm run dev                   # http://localhost:3000
```

### Обновление с предыдущей версии

Распакуйте новые файлы поверх старых (не трогайте `backend/.env` и `node_modules`), затем:

```bash
cd backend
npx prisma generate
npx prisma migrate deploy     # применит 0002_user_libraries
```

Новых npm-зависимостей нет. Миграция передаёт **все существующие треки первому администратору** (раньше их добавлял он), удаляет из избранного и плейлистов связи с чужими треками и разрешает загрузку всем пользователям.

## Личные медиатеки

- Каждый пользователь видит, слушает, загружает и **удаляет только свои треки**. Чужие треки недоступны ни в библиотеке, ни в поиске, ни по прямой ссылке на стрим.
- Файлы пользователя лежат в `MUSIC_DIR/users/<id пользователя>/`. Два пользователя могут загрузить один и тот же файл — у каждого будет своя копия.
- Удаление трека удаляет и файл с сервера (иначе его вернуло бы следующее сканирование).
- Плейлисты и избранное тоже личные. Публичные плейлисты отключены: они раскрывали бы чужие файлы.
- **Админ** по-прежнему видит общую картину: пользователи, нераспознанные треки (с указанием владельца), запросы, статистика. Админ может отозвать у пользователя право загрузки и удалить пользователя вместе с его треками.
- **Сканирование папки сервера** (админ-панель): файлы в `MUSIC_DIR/users/<id>/` достаются этому пользователю, остальные файлы из `MUSIC_DIR` — администратору, запустившему сканирование.
- **Запросы треков:** администратор может загрузить файл прямо в медиатеку запросившего (кнопка «Загрузить для …» в админ-панели) — запрос закроется автоматически.

## Импорт плейлиста из Spotify

Раздел **Импорт** создаёт плейлист из тех треков списка, что уже есть в вашей медиатеке. Недостающие показываются списком, их можно загрузить самому или одним нажатием запросить у администратора.

**Способ 1 — вход через Spotify** (OAuth Authorization Code + PKCE, всё выполняется в браузере):

1. На [developer.spotify.com/dashboard](https://developer.spotify.com/dashboard) создайте приложение.
2. В **Redirect URI** укажите `http://127.0.0.1:3000/import` (Spotify не принимает `localhost`, поэтому откройте Loral по адресу `http://127.0.0.1:3000`).
3. Скопируйте **Client ID** в `backend/.env` → `SPOTIFY_CLIENT_ID=…` и перезапустите сервер.
4. В Loral: Импорт → «Войти через Spotify» → «Перенести» у нужного плейлиста.

Ограничения Spotify (действуют с февраля 2026, [источник](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide)): приложение в режиме разработки требует Premium у владельца приложения и допускает до 5 пользователей; содержимое отдаётся только для плейлистов, которые вы создали или ведёте совместно.

**Способ 2 — без входа:** выгрузите плейлист в CSV через [exportify.net](https://exportify.net) и загрузите файл на вкладке «Файл или текст». Подходит и обычный список «Исполнитель - Название» по строке на трек. Работает для любых плейлистов и не требует настройки.

## Как устроено

**Имя файла.** `Исполнитель - Название.ext` делится по *первому* ` - `, поэтому `Jay-Z - Song - Part 2.flac` даёт исполнителя `Jay-Z`. Если имя не подходит, читаются теги; если и их нет — трек получает статус `NEEDS_REVIEW` и попадает в админ-панель на ручную правку.

**Загрузка.** Drag-and-drop, несколько файлов, прогресс. Правило имени проверяется на клиенте и на сервере *до* сохранения файла.

**Обогащение (BullMQ).** При появлении трека и раз в 24 часа: iTunes → Last.fm (нужен `LASTFM_API_KEY`) → MusicBrainz. Заполняются жанры (основной и поджанры), год, альбом, длительность, обложка (сохраняется локально). Заполненные вручную поля не перезаписываются.

**Авторизация.** JWT access (15 мин) + refresh (30 дней, в БД хранится хэш, ротация при обновлении). Блокировка пользователя действует сразу.

**Стриминг.** HTTP Range, `206 Partial Content`, `416` для неверных диапазонов.

**Плеер.** Один `<audio>` в layout группы `(app)` — музыка не прерывается при навигации. Очередь, shuffle, repeat, перемотка, медиа-клавиши.

**Discover.** Чарты стран, новинки, жанры; сопоставление с вашей медиатекой: свой трек играет полностью, остальные — 30-секундным превью или поиском на YouTube, плюс кнопка «Запросить трек».

## Заметки

- Next проксирует `/api/*` на бэкенд. Для очень больших файлов укажите `NEXT_PUBLIC_API_URL=http://host:4000/api` и `CORS_ORIGIN` на адрес фронтенда.
- За reverse-proxy включите HTTPS и не отключайте заголовок `Range`.
